    Where what you say goes. On a default build nothing you type leaves this machine: the
    browser talks only to this simulator, and the simulator is the MCP client and talks only to
    the MCP server, over Streamable HTTP on loopback. Started against a hosted model or a hosted
    voice that stops being the whole truth, which is why the line above names every hosted
    service actually in use rather than leaving you to assume. Push-to-talk is separate
    again. On the browser path your audio is sent to that browser’s own speech service
    — in Chrome, that is Google — and never reaches this simulator. On the other path
    your audio is posted here as 16 kHz mono PCM, and what happens to it next depends on
    how this simulator was started —  Sending a
    recording of a voice takes its own switch, --live-transcribe, which nobody can
    turn on by accident, and which is not implied by running the model or the voice live. The
    note beside the push-to-talk button says which path is active, before you press it.
  
      
  
      
    Both voice paths are read by the same normaliser and both stop at the same confirmation, so
    nothing is asked of the server until you have seen what was heard. Typing is the path
    everything is tested on, and it always works.
